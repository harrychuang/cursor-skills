Design Token Architecture

Figma M3 Variables

在 Figma 中建立、套用、稽核與理解 Variables 的完整 Agent Skill。 遵循 Google Material Design 3 的三層 Token 繼承模型，讓設計與程式碼共用同一套語意化命名。

Reference System Component Ref → Sys → Comp

三層架構

每一層回答不同的問題，且不可跨層混用命名職責。

Ref 原始值

Reference — 這個值本身是什麼？

存放 hex 色碼、px 數值、字重等原始資料。名稱必須直覺反映數值本身，不可出現元件或版面區域名稱。

{prefix}/ref/palette/primary/40
Sys 語意角色

System — 產品共用的語意是什麼？

將 Ref 映射為跨元件共用的語意角色（primary、error、inset-md 等）。不可綁定單一元件的解剖結構。

{prefix}/sys/color/primary
Comp 元件綁定

Component — 這個元件如何使用 Token？

只有這一層可以出現 button、card、padding-horizontal 等元件與結構名稱。Comp 必須 alias 到 Sys，而非直接指向 Ref。

{prefix}/comp/filled-button/container/background-color
ref/palette/primary/40 → sys/color/primary → comp/filled-button/container/background-color → Figma Node

前置條件：每次呼叫 use_figma 前必須先讀取 figma-use skill，且必須傳入 skillNames: "figma-m3-variables"。所有 use_figma 呼叫必須依序執行，不可平行。

通用規則

適用於所有工作流程（A / B / C / D / E）的強制規則，批次寫入必須先 dry-run。

  1. Inspect before Write 每次寫入前先以唯讀 use_figma 確認目前狀態，再執行寫入操作。
  2. ALL_SCOPES 禁止使用 必須依 Token 角色設定明確的 scope，不可使用 ALL_SCOPES 或非 Ref 空 scope。
  3. 必須設定 WEB code syntax 格式固定為 var(--{prefix}-{layer}-{name})，例如 var(--md-sys-color-primary)。
  4. 回傳所有 ID 每個建立或修改腳本都必須 return 所有受影響的 variable ID 與 node ID。
  5. Prefix 一旦確認即固定 整個 session 使用同一 prefix（如 md、dd、bd），不可混用。
  6. use_figma 嚴格依序 絕不可同時平行執行兩個 use_figma 呼叫。
  7. 優先綁定 Comp Token 元件節點應優先綁定 comp token；只有頁面級共用語意或缺少 comp token 時才使用 sys，不得直接綁定 ref。
  8. 批次寫入先 Dry-run 任何超過一個 node 的綁定都必須先回傳 binding plan，除非使用者明確要求直接 auto-apply。
  9. 錯誤處理 發生錯誤時停止、閱讀錯誤訊息、修正後重試 — 不可盲目重試。

命名哲學

三層各有不同的命名職責。建立、套用或稽核 Variables 時，必須嚴格區分。

Ref 允許

  • ref/color/red/50
  • ref/spacing/16
  • ref/radius/12
  • ref/type/size/14

Ref 禁止

  • button、card、chip
  • bottom-bar、top-app-bar
  • ref/spacing/button/padding-h

Sys 允許

  • sys/color/primary
  • sys/spacing/inset-horizontal-md
  • sys/shape/corner-full

Sys 禁止

  • sys/spacing/button-padding-h
  • sys/color/top-app-bar-surface

Comp 元件結構命名

只有 Comp 層可以出現元件與解剖結構名稱，且必須 alias 到 Sys：

  • comp/filled-button/container/padding-horizontal → sys/spacing/inset-horizontal-md
  • comp/text-field/label-text/color → sys/color/on-surface-variant
  • comp/navigation-bar/container/background-color → sys/color/surface-container

Collection 命名

結構選項 Collection 名稱
三個獨立 Collection（建議） {Prefix} · Reference / {Prefix} · System / {Prefix} · Component · {ElementName}
單一 Collection {Prefix} · Design Tokens（以 group prefix 區分三層）

WEB Code Syntax

所有 Variable 都必須設定 WEB code syntax，供設計到程式碼的 handoff 使用。

var(--{prefix}-{layer}-{category}-{name})
#6750A4
md/ref/palette/primary/40 var(--md-ref-palette-primary-40)
primary
md/sys/color/primary var(--md-sys-color-primary)
button fill
md/comp/filled-button/container/background-color var(--md-comp-filled-button-container-background-color)

規則：層級以 - 分隔（非 /），全小寫，空格替換為 -。Ref 保持簡短且值導向；長元件路徑只存在於 comp- 下。

依 Token 角色設定 Figma scope。Scope 主要控制 picker 可見性；Plugin API 綁定仍需另外驗證型別與屬性相容性。

五大工作流程

依觸發情境選擇對應流程。所有流程共享上方的通用規則。

A

套用現有 Variables 到元件

觸發：使用者提供 Figma URL + node-id、目前 selection 或單一元件，要求套用 Variables

  1. Inspect — 列出 variable collections、variables 與目標 node anatomy
  2. Evaluate — 確認命名符合 M3 三層結構；若缺失則切換至 Workflow B
  3. Match — 依元件類型找出 Comp 層 token，列出綁定提案供使用者確認
  4. Bind — 執行綁定（fills、strokes、radius、padding、gap、text、typography）
  5. Validate — 檢查 boundVariables 並呼叫 get_screenshot
B

建立 Variables（檔案中尚無）

觸發：檔案中找不到 M3 三層 Variables，或使用者明確要求建立

  1. Discover — 探索設計指南；若無則以 AskQuestion 收集視覺風格偏好
  2. Ask prefix — 讓使用者選擇 prefix（md、dd、bd 或自訂）
  3. Ask Collection 結構 — 三個獨立 Collection（建議）或單一 Collection
  4. Inspect — 確認無重複 Collection 名稱
  5. Create — 依 token-spec 建立 Ref（原始值）→ Sys（alias Ref）→ Comp（alias Sys）
  6. Bind — 執行 Workflow A Step 4 綁定到目標節點
  7. Validate — 截圖確認並回報各層 variable 數量
C

稽核現有 Variables

觸發：使用者要求檢查、稽核，或詢問「命名是否正確？」

  1. Inspect — 讀取所有 collections、variables、scopes、codeSyntax、valuesByMode
  2. Apply audit-rules — 依 alias、scope、syntax、mode、型別與命名規則編列問題清單
  3. Report — 以表格呈現：違規變數名稱、違規類型、建議修正
  4. Ask — 詢問是否自動修正
  5. Validate — 修正後再次 inspect，確認零違規
D

從現有 Variables 設計元件

觸發：使用者希望 AI 理解現有 token 並用它們建立或更新元件

  1. Discover guidelines — 掃描 paint styles、text styles、components；有則摘要確認，無則 AskQuestion 收集偏好
  2. Inspect variables — 分析三層結構與 token 語意
  3. Semantic mapping — 對照 design guidelines，衝突時標記給使用者
  4. Variants & states — 以 AskQuestion 讓使用者選擇變體維度與互動狀態
  5. Plan state tokens — 確認現有 Comp token 是否涵蓋各狀態，不足則新增
  6. Build — 建立 Component 或 Component Set，綁定 variables
  7. Validate — 截圖確認視覺正確且各狀態可區分
E

批次套用 Variables 到既有元件

觸發：使用者要求套用到多個 selected nodes、Component Set、目前 page 或符合名稱的元件

  1. Define scope — 確認 selection、Component Set、page 或 name pattern
  2. Inspect candidates — 讀取 anatomy、layout、paint、text 與既有 boundVariables
  3. Classify — 依 token-spec component patterns 標記 exact / inferred / unknown
  4. Dry-run plan — 回報 bind / review / skip 與 missing tokens 統計
  5. Confirm — 使用者確認後才批次寫入；review 項目不得靜默套用
  6. Apply & Validate — 重新抓取 IDs、驗證型別、套用、再 inspect 與截圖

變體與互動狀態

狀態 token 作為 Comp token 路徑的子屬性。M3 標準 state layer 不透明度如下。

State Token 命名

  • …/background-color — Default
  • …/background-color/hovered
  • …/background-color/focused
  • …/background-color/pressed
  • …/background-color/disabled
  • …/background-color/error

State Layer 不透明度

  • Hovered — 8%
  • Focused — 12%
  • Pressed — 12%
  • Dragged — 16%

Disabled 覆寫規則

  • Container fill → on-surface @ 12%
  • Label / icon → on-surface @ 38%
  • Outline → on-surface @ 12%

Disabled 狀態必須建立專用 token，不可重用 Default token。不透明度應透過 node 的 opacity 或 OPACITY variable 設定，不可 bake 進 color token 值。

Light / Dark 雙模式擴展

Sys 層 Collection 可新增 Dark mode。每個 Sys color token 在 Dark mode 指向不同的 Ref palette token。Comp 層與節點綁定無需修改。

// Light mode
sysPrimary.setValueForMode(lightModeId, { type: 'VARIABLE_ALIAS', id: refPrimary40.id })
// Dark mode
sysPrimary.setValueForMode(darkModeId,  { type: 'VARIABLE_ALIAS', id: refPrimary80.id })

稽核規則 — 十一種違規類型

Workflow C 使用的完整違規偵測清單。零違規時回報「All Variables comply」。

1

跨層直接 Alias（Comp → Ref，跳過 Sys）

Comp 層 variable 直接 alias 到 Ref 層。修正：建立缺失的 Sys token，更新 Comp 指向正確 Sys。

2

Scope 使用 ALL_SCOPES 或非 Ref 空 scope

scopes 包含 ALL_SCOPES 或非 Ref 層的空 scope。Scope 是 picker 治理規則，修正時依 scope 對照表設定明確 scope。

3

缺少或不正確的 WEB Code Syntax

codeSyntax.WEB 為空、不存在，或與 canonical var(--prefix-layer-name) 不一致。修正：從 variable 名稱自動推導並覆寫。

4

Prefix 不一致

同一檔案混用多個 prefix（如 md 與 bd）。修正：確認正確 prefix 後批次重新命名。

5

Ref 層 Variable 直接綁定到節點

節點視覺屬性直接綁定 Ref 層 variable。修正：重新綁定到對應 Sys 或 Comp token。

6

空 Collection

Collection 存在但 variableIds 為空。修正：詢問使用者是否刪除。

7

Ref 或 Sys 使用元件 / 區域特定命名

Ref/Sys 名稱包含 button、bottom-bar 等僅屬 Comp 的詞彙。修正：Ref 改為 primitive 路徑，Sys 改為通用語意，Comp 新增 alias。

8

Alias 方向不合法

Ref 必須存 raw value，Sys 只能 alias Ref，Comp 只能 alias Sys。修正：重建正確 Ref → Sys → Comp 鏈。

9

缺少 Mode 值

Variable 在 collection 的某些 mode 中沒有 valuesByMode。修正：為缺值 mode 設定 raw value 或正確 alias。

10

綁定型別與節點屬性不相容

例如 FLOAT 綁到 fill color 或 COLOR 綁到 radius。修正：重新綁定到 resolvedType 相容的 variable。

11

元件節點略過既有 Comp Token

Component node 直接綁 Sys，但已存在對應 Comp token。修正：改綁 matching Comp token，保留元件層控制。

與其他 Skill 的分工

此 skill 專注 Figma Variables 的 M3 三層管理，與程式碼端治理及完整 design system 建置互補。

Skill 職責
figma-use 底層 Plugin API 規則（顏色 0–1、return、page switching 等）— 必須優先讀取
