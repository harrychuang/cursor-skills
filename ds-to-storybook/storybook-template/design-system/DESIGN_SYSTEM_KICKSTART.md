# Design System Extraction Kickstart

This package holds a design-system specification extracted from the references listed below. It defines rules and tokens only: do not implement product screens, scaffold app routes, or invent a landing page here. Product implementation begins after the user approves the checkpoint in `SESSION_STATE.md`.

## References

List screenshots, graphic/brand/editorial references, Figma design URLs (the full `figma.com/design/<file-key>/...` link written verbatim, also recorded in `SESSION_STATE.md` under Figma file URL), rendered routes, native app captures, project folders, and prototype sources here. Each one also gets a `Source Inventory` row in `DESIGN_EVIDENCE_MAP.md`.

## Package Guide

Files are filled in this order (SKILL.md Workflow steps 1-9):

1. `DESIGN_EVIDENCE_MAP.md` — Source Inventory with fingerprints and evidence tiers, Source Duplicate Review, Evidence.
2. `DESIGN_ELEMENTS.md` — foundations; `DESIGN_PRINCIPLES.md` — 5-7 principles (Deep Extract, or Character Pass).
3. `TOKEN_ARCHITECTURE.md` + `tokens/tokens-ref.css`, `tokens-sys.css`, `tokens-comp.css` — near-token decisions recorded before `sys`/`comp` tokens are written.
4. `COMPONENT_INVENTORY.md` — patterns with Category and Status; Component Similarity Review when candidates overlap.
5. `components/<component-name>.md` — specs from `COMPONENT_SPEC_TEMPLATE.md` (Quick: 1-3 components; Deep: all).
6. `ANTI_AI_STYLE_RULES.md` (always); `PAGE_COMPOSITION_RULES.md`, `INTERACTION_STATES.md` (Deep Extract, or Character Pass).
7. `docs/design-system/index.html` and `review.html` — generated by `node <skill-root>/scripts/extract_check.mjs <target-root> --locale <ui-locale>`, which also runs the strict audits.
8. `SESSION_STATE.md` — updated at every checkpoint; `Mode` records `quick` or `deep`, `Intake` records `none`, `web-project`, or `native`.

Quick Extract leaves `DESIGN_PRINCIPLES.md`, `PAGE_COMPOSITION_RULES.md`, and `INTERACTION_STATES.md` as stubs whose first content line reads `Status: deferred to Character Pass`. `INTEGRATION_REVIEW.md` is created only by the Collaboration Review And Integration Pass.
