快速上手

讓 AI 從截圖或 Figma 建立並對齊 UI

Create Design Workspace Skill 可以讓 AI 從 UI 截圖或 Figma 自動建立可開發的工作空間，自動整理相對應的頁面、元件、foundation 文件與 token 樣式設定，再以「設計系統」優先建立共用樣式，讓產品實作更穩定對齊設計。

使用步驟

第一次使用只要記住這 4 件事

每一步都有明確的下一個檔案或指令。生成後不要猜流程，直接從 `start-here/KICKSTART.md` 繼續。

1

準備空資料夾

建立新的目標資料夾，避免和既有產品專案混在一起。

2

放入設計來源

使用截圖、Figma URL，或兩者一起作為輸入。

3

執行 bootstrap

建立 template、reference、product docs、foundation docs 與 scripts。

4

從 KICKSTART 繼續

進入 workspace 後執行 init，再照 Storybook-first 的順序開發。

使用前先確認

你只需要準備少量資訊

最好的起點是清楚的設計輸入與空白 workspace。Figma-first 可以更完整，但不是必須。

你需要準備

  • 新的目標資料夾名稱
  • 一張以上 UI 截圖，或一個 Figma design URL
  • 想做的產品或頁面名稱
  • Node.js 18.17 以上

先不要這樣用

  • 不要直接在既有 app root 裡執行
  • 不要在沒有設計來源時開始
  • 不要跳過 `start-here/KICKSTART.md`
  • 不要先做畫面再補 foundation

產出內容

Bootstrap 後會得到什麼

產出的不是一個空殼，而是一個讓 agent 能繼續分析、建 Storybook、組畫面與做視覺對齊的 workspace。

reference/ 保存截圖與輸入來源
start-here/ 工作順序、KICKSTART 與任務
design/foundations/ 顏色、字體、間距、圓角與 token 指南
src/stories/ Storybook foundation docs
product/ PRD、screen manifest 與功能文件
scripts/ init、sync、check automation

Figma-first 分支

有 Figma 權限時，先做 token 再實作

如果 `.env.local` 有 Figma URL 與授權，流程會先跑 Phase 0：抽取或檢查 variables，建立 Ref → Sys → Comp 的 token 層，再進入畫面與元件開發。
