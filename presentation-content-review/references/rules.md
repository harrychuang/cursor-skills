# 簡報內容審查規則集

- 規則版本：1.0.2（2026-09-15）
- 這份檔案是 `presentation-content-review` 的唯一規則來源。SKILL.md 只描述流程；每次審查都要先讀這裡，以這裡為準。
- 規則 ID 固定不變。新增規則用該組下一個空號；不要的規則標「已停用」並寫日期與原因，不刪除、不重新編號。
- 來源標記：**使用者規則** 是使用者明確提出的要求；**衍生規則** 是為了讓使用者規則可判定而補的檢查，使用者可要求停用。

## 嚴重度定義

| 嚴重度 | 意思 | 報告中的處理 |
| --- | --- | --- |
| 必改 | 不改就不符合這套簡報的基本要求 | 列入必改清單，總評不能是「可送出」 |
| 建議 | 改了會明顯更有說服力，不改仍可用 | 逐頁列出，附改法 |
| 可選 | 用字或順序的小調整 | 只在逐頁表提一句 |

### 整體判定門檻

- **可送出**：沒有必改項目，建議項目不影響任何一頁結論的可信度。
- **修改後可送出**：有必改項目，但都是單頁局部修正就能解決，例如改寫標題、補來源、移除一條無關證據。
- **需大幅修改**：任一頁需要整組更換證據、故事線（D1）不成立，或結論互相矛盾（D2）。

### 必改清單排序

依對整份簡報結論可信度的影響排序：整頁沒有有效證據（E1／E3）→ 標題不是完整結論（T1）→ 結論矛盾（D2）→ 疑似捏造（E5）；同一級依頁序。

## 判定用語

- 每項規則的判定只用三種：**通過**、**需修改**、**缺少**。
- 判定旁一定附依據：引用或轉述該頁原文，讓使用者能核對。

## A. 標題規則（T）

### T1 標題是一個結論：觀點＋行動

- 來源：使用者規則（2026-09-15 補充：結論由「觀點」與「行動」組成，理由放副標）
- 嚴重度：必改
- 結構：一頁標題只放一個結論。結論有兩個部分：**觀點**是講者的判斷（情況怎麼樣、哪個方向對）；**行動**是所以要做什麼。支撐這個結論的**理由**不放標題，放副標（見 S1）。
- 檢查方式：把標題單獨讀一遍，問兩個問題：「講者的觀點是什麼？」「他要我們做什麼？」兩個都答得出來才通過。
- 通過條件：同時含有一個觀點與一個行動（建議做、先做、停止做、改成、投入⋯⋯）。讀者只看這句就知道講者的立場與要求。「達到 X 就做 Y」這類決策條件式標題，條件本身就是觀點，算通過。
- 常見失敗：
  - 只有主題，沒有觀點也沒有行動：「新手引導優化」「市場現況」「競品分析」
  - 只有觀點，沒有行動：「新用戶流失率偏高」
  - 只有行動，沒有觀點：「導入 A/B 測試」（沒說為什麼這是對的方向）
  - 把理由塞進標題、擠掉行動：「因為六成新用戶在第三步離開」（理由應放副標）
  - 疑問句或空泛口號：「我們該如何提升留存？」「以使用者為中心」
- 判定備註：純封面、目錄、章節分隔頁、附錄可標「不適用」，但簡報主體的每一頁都適用。標題缺結論時，E1 仍照數候選證據並判需修改，E3 標「無法判定」；等標題改寫後再重判。

### T2 一頁一個主訊息

- 來源：衍生規則（讓 T1 可判定：一頁有兩個結論，就不知道證據在支持哪一個）
- 嚴重度：建議
- 通過條件：標題只有一個結論與一個行動；若有兩個以上結論，建議拆頁或合併成一個更上位的結論。
- 常見失敗：「建議縮短新手引導並重做定價頁」（兩件事，各需要各自的證據）。

### T3 標題可獨立閱讀

- 來源：衍生規則（結論式標題的目的就是讓讀者只看標題就能懂）
- 嚴重度：建議
- 通過條件：不依賴前一頁或內文就能理解；沒有未解釋的內部代號、縮寫。
- 常見失敗：「同上，改用方案 B」「P2 專案優先」。

## B. 副標規則（S）

### S1 副標用理由補充結論

- 來源：使用者規則（2026-09-15 補充：標題放結論，理由放副標）
- 嚴重度：建議（副標完全缺少時仍為建議，但若標題的結論沒有任何理由支撐，會在 E1 反映）
- 檢查方式：把副標接在標題後面，加上「因為」讀一遍是否通順。
- 通過條件：副標是支撐標題結論的理由：回答「為什麼這個觀點成立」或「為什麼現在要做這個行動」，可以是原因、觀察到的問題、關鍵數據或風險。理由與證據的分工：副標用一句話講理由，內文用 1–3 個證據證明理由成立（見 E 組）。
- 常見失敗：
  - 重複標題換句話說
  - 當目錄用：「包含現況、做法、時程」
  - 寫成第二個結論或另一個行動
  - 空泛形容：「提升整體體驗」

### S2 副標不重複標題、不當目錄

- 來源：衍生規則（S1 的常見失敗獨立成可判定項）
- 嚴重度：可選
- 通過條件：副標提供標題沒有的資訊，且不是內文章節清單。
- 判定備註：只在 S1 通過時才判 S2；副標已因目錄式或重複標題命中 S1，不重複報 S2。

## C. 證據規則（E）

### E1 每頁 1–3 個證據

- 來源：使用者規則
- 嚴重度：0 個為必改；超過 3 個為建議
- 檢查方式：數內文裡「能拿來證明標題結論」的獨立項目。同一個產品的同一次成果只算一個，即使拆成三個 bullet。多個產品列在同一句主張下、各自都沒有成果時，合算一個「業界普遍做法」證據。被 E3 判為無關的證據不計入。
- 通過條件：1 到 3 個。
- 常見失敗：
  - 0 個：內文只有做法說明、流程圖、時程，沒有任何佐證
  - 超過 3 個：一長串案例或數字，讀者抓不到重點
  - 把「我們打算做的事」當證據
- 處理方式：超過 3 個時，指出最直接支持結論的 1–3 個保留，其餘建議移到附錄或拆頁。

### E2 證據四要素：主體、做法、成果、來源

- 來源：使用者規則（使用者要求「哪些產品做了這個功能，獲得的成長和成果是什麼」）
- 嚴重度：缺成果或缺來源為建議；四要素全缺為必改（等同無證據）
- 每個證據檢查四項：
  1. **主體**：哪個產品、團隊、或自家的哪份數據／研究
  2. **做法**：做了什麼功能或改變（要具體到能看懂怎麼做）
  3. **成果**：得到什麼成長或結果；有數字就要有單位、期間、比較基準
  4. **來源**：連結、文件名稱、研究名稱或「使用者提供的資料」；不能是「聽說」「網路上看到」
- 通過條件：四項齊全。缺項要逐一列出，讓補件的人知道要補什麼。
- 證據類型不限：外部產品案例、自家產品數據、使用者研究、第三方報告都可以，只要四要素齊全。

### E3 證據要直接支持該頁的結論

- 來源：使用者規則（使用者要求證據「輔助這個結論」）
- 嚴重度：無關為必改；部分相關為建議
- 檢查方式：把證據和標題放在一起，問「如果這個證據是真的，標題的結論會更可信嗎？」
- 判定分三級：
  - **直接支持**：通過。
  - **部分相關**：只證明問題存在、使用者有需求或有人這樣做，沒證明這個做法有效。判需修改、列建議，並在待補清單補一項成效證據。
  - **無關**：判缺少。該條不計入 E1；若因此該頁證據為 0，E1 必改。
- 通過條件：證據直接支持標題裡的判斷或行動，而不只是跟主題有關。
- 常見失敗：
  - 標題講縮短新手引導，證據講競品改了定價頁
  - 證據支持「這個問題存在」，但標題結論是「應該用某個做法解決」，中間缺一步
  - 同一份證據在不同頁支持不同結論（見 D3）

### E4 標示證據強度

- 來源：衍生規則（避免把「別人有這個功能」當成「這樣做有效」）
- 嚴重度：建議
- 每個證據標一種強度：
  - **已驗證成效**：有可查的成果數據與來源
  - **做法參考**：確認對方有這個做法，但成效未確認（截圖、功能說明屬於這類）
  - **預期／待驗證**：推論或自家尚未驗證的假設
- 通過條件：報告裡每個證據都有強度標示；簡報原文若把「做法參考」寫得像「已驗證成效」，標為需修改。
- 他人的成效要寫成「該團隊回報」，不能寫成我們必然得到的結果。
- 判定備註：強度標的是這條資料本身可不可靠；它證明的是什麼（問題存在、使用者需求、做法、成效）寫在「支持結論」欄，不混在強度裡。自家有數字、有來源的數據或研究標「已驗證（自家數據）」。他人只說「有提升」但沒數字沒連結，補齊前算做法參考，並註明「該團隊回報、未量化」。

### E5 不捏造、不誇大

- 來源：衍生規則
- 嚴重度：必改
- 通過條件：數字、案例、來源都能對回原文或使用者提供的資料；沒有把推算寫成事實，沒有省略不利的比較基準。
- 判定備註：只在有捏造或誇大跡象時觸發：數字與來源對不上、來源查無此文、推算寫成事實、省略不利基準。單純缺來源或缺數字歸 E2，不算 E5。
- 審查者自己也受此規則約束：改寫建議裡缺的證據一律寫「【待補：需要什麼】」，不填造。

## D. 整體規則（D）

### D1 只讀標題能串成完整論述

- 來源：衍生規則（T1 在整份簡報層級的檢查）
- 嚴重度：建議
- 檢查方式：把所有主體頁的標題依序抄成一段話，讀一遍。
- 通過條件：這段話本身就是完整的主張：問題是什麼、建議做什麼、為什麼、下一步。
- 常見失敗：標題之間跳躍、缺少「所以要做什麼」的收尾頁。

### D2 結論之間不互相矛盾

- 來源：衍生規則
- 嚴重度：必改
- 通過條件：沒有兩頁的結論互相衝突，或前頁的行動被後頁的結論否定而沒有說明。

### D3 同一證據不重複支撐不同結論

- 來源：衍生規則（E3 的整體層級檢查）
- 嚴重度：建議
- 通過條件：同一個證據若出現在多頁，只支持同一個結論，或明確說明它同時支持哪幾個面向。
