Design System Extractor

從參考畫面到可執行規範

這份簡報說明 extractor 如何把 screenshots、Figma 和專案線索整理成 evidence、tokens、components、HTML docs 和 audit 結果。

Problem

沒有規範時，AI 和人都會開始猜

來源重複

同一份截圖或 Figma node 被誤算成多份 evidence。

Token 漂移

接近的顏色、間距和字級被拆成太多 raw values。

Component 重複

相似元件被建立成多個版本，之後難以維護。

Flow

五個階段

流程的重點是先建立 evidence，再把 evidence 轉成規範。 中間遇到近似或重複，就進 review queue。

  1. 收集來源

    Screenshots、Figma、routes、CSS、tokens。

  2. 建立 evidence map

    每個判斷都能追溯來源和信心等級。

  3. 整理 tokens

    維持 ref -> sys -> comp。

  4. 盤點 components

    比較 fingerprint，再決定 merge 或 variant。

  5. 文件與 audit

    產生 docs、review queue、audit result。

Review gates

三個決策必須明確記錄

Source duplicate reuse existing source、ignore duplicate、keep distinct。
Near token merge 或 keep distinct；色階固定 100 最亮、0 最暗。
Similar component merge、make variant、keep distinct，或 blocked pending evidence。

Outputs

交付的是可接手的 package

Source of truth

design-system/*.md 與 tokens/*.css。

Reading layer

docs/design-system/index.html 與 review.html。

Checkpoint

SESSION_STATE.md 記錄狀態、問題和下一步。

Takeaway

Extractor 讓設計判斷可追溯、可審查、可重用

對開發者來說，最重要的是不要跳過 checkpoint： 先確認 evidence、review decisions 和 audits，再進入產品 UI 實作。
