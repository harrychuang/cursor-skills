Design Token Architecture

Figma M3 Variables

在 Figma 中建立、套用、稽核與反推 Variables 的 Agent Skill。 遵循 Material Design 3 的三層 Token 繼承，涵蓋色彩、文字、圓角、間距、尺寸、描邊寬度、透明度與陰影， 而且綁定 token 之後，設計稿的外觀維持不變。

Reference System Component Ref → Sys → Comp Workflow A–F

三層架構

每一層回答不同的問題，且不可跨層混用命名職責。

Ref 原始值

Reference — 這個值本身是什麼？

存放 hex 色碼、px 數值、字重、字型名稱等原始資料。名稱直接反映數值，不可出現元件或版面區域名稱；scope 一律為空，不出現在挑選器中。

{prefix}/ref/palette/primary/40
Sys 語意角色

System — 產品共用的語意是什麼？

把 Ref 對應成跨元件共用的語意角色（primary、inset-horizontal-md、corner-full、label-large 等），不可綁定單一元件的結構。

{prefix}/sys/color/primary
Comp 元件綁定

Component — 這個元件如何使用 Token？

只有這一層可以出現元件、variant、狀態與結構名稱（button、disabled、container、label-text 等）。Comp 必須 alias 到 Sys，不能直接指向 Ref。

{prefix}/comp/filled-button/container/background-color
ref/palette/primary/40 → sys/color/primary → comp/filled-button/container/background-color → Figma Node

前置條件：第一次呼叫 use_figma 前先讀 figma-use skill，每次呼叫都要傳入 skillNames: "figma-m3-variables"。use_figma 每次呼叫都從第一頁開始，也不能一次載入所有頁面，跨頁作業要逐頁執行。提問時使用編輯器的提問工具（Cursor 為 AskQuestion、Claude Code 為 AskUserQuestion）；沒有提問工具時，以文字詢問並等待回覆再寫入。

選擇工作流程

依使用者的需求選擇流程。目標不明確時，先詢問節點連結、選取範圍、section、page 或 component set，再做任何寫入。

使用者的需求 流程
把現有 Variables 套用到一個節點或目前的選取範圍A
檔案還沒有 tokens，要建立一套新的 token 系統B
檢查命名、alias 鏈、scope 或 token 覆蓋率C
用現有 tokens 建立新元件D
把現有 Variables 套用到整頁、多個元件或 component setE
把既有設計稿中寫死的數值轉成 tokensF
只想知道有哪些 tokens，不做任何修改只盤點（P2）

A 或 E 遇到沒有對應 token 的數值時，改走 F：從設計稿反推的 tokens 能維持原本的外觀。只有使用者想要一套可能改變外觀的新系統時才走 B。把散圖層做成元件屬於 figma-componentize，它會呼叫 F 處理 tokens。

通用規則

適用於所有工作流程的規則。

  1. 先檢查再寫入每次寫入前，先以唯讀的 use_figma 確認目前狀態。
  2. 一次一個呼叫use_figma 不可平行執行。寫入腳本要依 ID 重新取得節點與 variables、檢查型別是否相符，並回傳所有受影響的 variable、style 與 node ID。
  3. 先從檔案推斷慣例prefix、collection 結構、文字與陰影的綁定模式、階梯、狀態命名與 Ref 色彩分類都先從檔案推斷；檔案沒有線索才詢問，確認後整個 session 固定。
  4. 三層方向Ref 只存原始值（scope 為空）；Sys 只 alias Ref；Comp 只 alias Sys；composed 色彩也遵守相同方向。節點不可綁定 Ref。
  5. 綁定目標單一值屬性綁 Comp token（沒有元件的頁面層級用法才綁 Sys）。文字與陰影綁定到 Styles，Styles 的欄位再綁 Sys tokens（Styles 模式，預設）；或改為在文字節點綁 Comp typography tokens（Variables 模式）。
  6. Scope 與 code syntaxSys 與 Comp 一律設定明確的 scope，禁止 ALL_SCOPES；每個 variable 都要有 WEB code syntax。
  7. 外觀不變綁定前比對 token 的解析值與節點目前的值；只要不同就是 Tier 3 變動，即使使用者說「全部套用」也要逐組確認。
  8. 不複製 library tokens目標已使用 library variables 時，不在本地建立相同角色的 variables。
  9. 分批寫入每次寫入最多 100 個綁定，或一個元件。
  10. 錯誤處理發生錯誤時停止、閱讀錯誤訊息、修正原因後只重試該步驟，不盲目重試。

變動分級

每個寫入計畫在執行前先分級，由計畫中最高的級別決定確認方式。

級別 內容 確認方式
Tier 0
唯讀		盤點、檢查、收集數值、稽核報告、dry-run 計畫不需確認
Tier 1
單一目標，外觀不變		在使用者指定的一個節點綁定數值相同的 token，或為它建立最多 10 個 variables顯示對應表後等待確認；使用者明說直接套用則可略過
Tier 2
批次或結構性，外觀不變		跨多個節點綁定、建立 collection 或 mode、一次建立超過 10 個 variables、建立或修改 Styles、從節點 detach Style、改名、把 paint 透明度移到圖層透明度dry-run 計畫後等待確認；使用者明說不需審閱即可略過
Tier 3
改變外觀或具破壞性		綁定數值不同的 token、合併近似值、把數值貼齊階梯、修改已被使用的 token 值或 alias、刪除、移除綁定、更換 prefix附視覺證據，逐組取得確認；任何「全部自動套用」都不能略過

每次確認都會列出

  • 各層要建立的 variables 與 styles 數量
  • 依元件或節點分組的綁定，並列目前的值與 token 的值
  • 每個對應的信心度：exact、inferred、needs-review
  • 每個會改變外觀的項目都有標記
  • Tier 3：每個受影響範圍的基準截圖，加上近似值比對板連結或變更後預覽

命名哲學

三層各有不同的命名職責。建立、套用或稽核 Variables 時，必須嚴格區分。

Ref 允許

  • ref/color/blue/50
  • ref/spacing/16
  • ref/radius/9999
  • ref/type/size/14

Ref 禁止

  • button、card、chip
  • bottom-bar、top-app-bar
  • ref/spacing/button/padding-h

Sys 允許

  • sys/color/primary
  • sys/spacing/inset-horizontal-md
  • sys/shape/corner-full
  • sys/typescale/label-large/size

Sys 禁止

  • sys/spacing/button-padding-h
  • sys/color/top-app-bar-surface

Comp 元件結構命名

順序為 comp/{component}[/{variant}][/{size}][/{condition}][/{state}]/{anatomy}/{property}，必須 alias 到 Sys：

  • comp/filled-button/container/padding-horizontal → sys/spacing/inset-horizontal-xl
  • comp/filled-button/disabled/container/background-color → composed（on-surface + 12%）
  • comp/button/filled/hovered/state-layer/opacity → sys/state/hover/state-layer-opacity

Collection 結構

結構 Collection 名稱 使用時機
新檔案預設{Prefix} · Reference / {Prefix} · System / {Prefix} · Component（Component 內以群組區分元件）檔案還沒有 token collection
每個元件一個{Prefix} · Component · {ElementName}使用者偏好，或檔案已使用
單一 Collection{Prefix} · Design Tokens（以群組區分三層）檔案已使用

既有檔案一律沿用原本的結構。Light / Dark 兩個 mode 需要付費方案：Starter 每個 collection 只有 1 個 mode，Professional 10 個、Organization 20 個；每個 collection 最多 5,000 個 variables。

命名編碼

名稱要能直接轉成合法的 CSS 自訂屬性，Ref 名稱也要能反推出數值，供稽核規則 12 比對。

規則 範例
每段只用小寫英數、-、_；不可使用 .、{、}，也不可以 $ 開頭inset-horizontal-md
小數點改用 _0.5 → ref/type/tracking/0_5
負數加上 neg-−0.25 → ref/type/tracking/neg-0_25
透明度用百分比整數38% → ref/opacity/38
色彩 tone 取 CIE L* 四捨五入（M3 HCT 的 tone 就是 L*）#1A73E8 → ref/color/blue/50
帶 alpha 的色彩加 -a{百分比}#000000 15% → ref/color/neutral/0-a15
全圓圓角ref/radius/9999
兩個不同的值撞名：使用次數多的保留原名，其他加 -b、-cref/color/blue/50-b
一個名稱不可同時是另一個 variable 的群組前綴避免 …/background-color 與 …/background-color/hovered 並存

Sys 語意詞彙

檔案沒有 Sys tokens 時使用的預設詞彙；檔案已有的階梯永遠優先。

色彩角色（M3）

  • Accent：primary、on-primary、primary-container、on-primary-container，secondary、tertiary 同理
  • Error：error、on-error、error-container、on-error-container
  • Surface：surface、on-surface、on-surface-variant、surface-dim、surface-bright、surface-container-lowest … surface-container-highest
  • Outline / Inverse / Utility：outline、outline-variant、inverse-surface、inverse-on-surface、inverse-primary、scrim、shadow
  • 延伸：success、warning 系列（M3 沒有），以及選用的 fixed 角色

間距：角色 × 單一階梯

名稱為 sys/spacing/{角色}-{標籤}。角色：inset-horizontal（左右 padding）、inset-vertical（上下 padding）、inset（四邊相同）、gap-inline（水平間距）、gap-stack（垂直間距）。同一個標籤在所有角色都代表同一個值。

文字與陰影

文字與陰影是由多個欄位組成的「複合屬性」，綁定方式和單一值屬性不同。

Styles 模式（預設）

  • 每個用到的 typescale role 建一個 Text Style，欄位綁定 Sys typescale variables
  • 每個用到的 elevation 等級建一個 Effect Style，陰影欄位綁定 Sys elevation variables
  • 節點套用 Style；不建立 Comp 的文字與陰影 tokens

Variables 模式

  • 文字節點直接綁 Comp tokens，例如 comp/filled-button/label-text/size
  • 已套用 Text Style 的節點很可能會被 detach，列為 Tier 2
  • 陰影直接綁 Sys elevation variables

模式判斷

  • 範圍內至少一半文字使用 Text Styles → Styles 模式
  • 否則文字節點已直接綁定文字 variables → Variables 模式
  • 兩者都沒有 → Styles 模式；計畫中會說明並提供切換方式

行高與字距 variables 只支援 px：百分比會依字級換算，AUTO 行高維持不綁定並列在報告中。字重以 FLOAT 綁定（Figma 會取最接近的字重），字型的樣式名稱不標準時改綁 fontStyle。

半透明色彩

填色綁定色彩變數後，很可能由變數的 alpha 決定透明度，原本 paint 的透明度不一定保留。因此 paint 透明度小於 100% 的填色，依序採用第一個可行的方法。

  1. Composed 色彩（2026-09-17 新增）建立一個 COLOR variable，值由「不透明的基底色 alias」加「COLOR_OPACITY scope 的透明度 alias」組成，填色綁定它。例如 comp/filled-button/disabled/container/background-color = sys/color/on-surface + sys/state/disabled/container-opacity（12）。沒有版本旗標可偵測，因此在已核准的寫入中直接嘗試，失敗就改用下一個方法並回報。
  2. 圖層透明度只適用於只有一個可見填色、沒有描邊、效果與子節點的圖層（例如 state layer、scrim）：填色綁不透明的 token、paint 透明度設為 100%，圖層 opacity 綁透明度 token。視覺等價，列為 Tier 2。
  3. 帶 alpha 的色彩其他情況綁定最終指向帶 alpha 之 Ref 色彩的 token 鏈，例如 ref/color/neutral/0-a12。

三種方法綁定後都會讀回，確認實際呈現的色彩與透明度不變。Ref 不能使用 composed 值；Sys 的 composed 值 alias Ref，Comp 的 composed 值 alias Sys。

六大工作流程

依觸發情境選擇對應流程。所有流程共用通用規則、變動分級與共用程序（P1 探索設計指南、P2 盤點 tokens、P3 檢查目標、P4 綁定、P5 驗證）。

A

套用現有 Variables 到單一目標

觸發：節點連結、目前的選取範圍或單一元件，加上套用 Variables 的要求

  1. 盤點與檢查 — P2，再對目標執行 P3
  2. 評估 — 有對應 token 就繼續；沒有 token 的數值改走 Workflow F；instance 改處理它的主元件；正確的既有綁定保留
  3. 計畫 — 每一列列出節點、屬性、目前的值、token、token 的值、信心度與級別
  4. 確認 — 依變動分級
  5. 綁定與驗證 — P4，再 P5
B

建立新的 token 系統

觸發：檔案沒有 token 系統，使用者要一套不從既有設計稿反推的新系統

  1. 探索設計指南 — P1；沒有指南時詢問產品類型、視覺風格、圓角偏好、品牌色與參考產品
  2. Prefix 與 collection 結構 — 先從檔案推斷，否則詢問；預設三個 collection
  3. 綁定模式 — 文字與陰影預設 Styles 模式
  4. 規劃 — 依詞彙表規劃色彩角色、間距階梯、圓角、typescale、elevation 與狀態透明度；只為使用者指定的元件建立 Comp tokens
  5. 確認（Tier 2）後建立 — Ref → Sys → Comp，再建立 Text Styles 與 Effect Styles
  6. 綁定與驗證 — 只綁使用者指定的目標，數值不同屬於 Tier 3；P5 並回報各層數量
C

稽核

觸發：要求檢查或稽核 token 的命名、結構或覆蓋率

  1. 盤點 — P2
  2. 執行規則 — variables 與 styles 的規則跑一次，節點規則逐頁執行
  3. 報告 — 18 類規則依嚴重度（error、warning、info）分組
  4. 詢問 — 使用者選擇要修正的項目，每個修正標示級別；近似重複的合併使用比對板
  5. 修正與重跑 — 修正後重跑受影響的規則，回報仍未解決的項目
D

從現有 Variables 設計元件

觸發：使用者希望 AI 用檔案中的 tokens 建立新元件

  1. 探索與盤點 — P1 與 P2
  2. 語意對應 — 容器、文字、圓角、間距對應到 tokens；與設計指南衝突時標記
  3. Variants 與狀態 — 讓使用者多選要包含的 variants 與互動狀態
  4. 規劃狀態 tokens — M3 順序；state layer 使用 on-{container} 色彩與 Sys 狀態透明度；disabled 使用 composed 色彩或圖層透明度；沿用檔案既有的狀態用字
  5. 建立 — Component 或 Component Set（參考 figma-generate-library Phase 3），variant 命名如 State=Hovered, Size=Medium；文字用 Text Styles，陰影用 Effect Styles
  6. 綁定與驗證 — P4 與 P5；截圖確認每個狀態都能區分
E

批次套用 Variables

觸發：多個選取的節點、component set、整頁，或符合名稱的元件

  1. 確認範圍 — 範圍太大時先詢問
  2. 盤點與檢查 — P2，再對每個候選節點執行 P3
  3. 分類 — exact / inferred / unknown
  4. Dry-run 計畫 — bind（數值相同的 exact）、review（inferred 或數值不同，屬 Tier 3）、skip；缺少的 token 改走 Workflow F
  5. 確認 — Tier 2 一次確認，Tier 3 另外逐組確認；review 項目不得靜默套用
  6. 分批套用與驗證 — P4，再 P5
F

把寫死的數值 token 化

觸發：分享節點、section、page 或元件並要求把寫死的樣式轉成 tokens；A 或 E 遇到沒有 token 的數值；figma-componentize 交來新建立的元件

  1. 範圍與基準截圖 — 超過 50 個頂層 frame 或跨頁時先確認範圍；寫入前替每個範圍截圖
  2. 推斷慣例 — P2
  3. 收集數值 — 逐頁執行、唯讀：色彩、文字、圓角、間距、尺寸、描邊寬度、透明度、陰影
  4. 完全相同的值 — 直接合併；檔案已有相同數值的 Ref 或 Sys token 就重用
  5. 近似值與不在階梯上的值 — 絕不自動合併；建立近似值比對板、截圖並提供連結，逐組詢問；合併屬於 Tier 3
  6. 語意與結構對應 — 對應到 Sys 角色與 Comp 結構並標示信心度；needs-review 的項目先詢問
  7. Token 計畫 — 列出並等待確認（Tier 2 以上）
  8. 寫入 — Ref → Sys → Comp → Styles → 綁定；半透明填色依序採用 composed 色彩、圖層透明度、帶 alpha 的色彩
  9. 驗證 — 讀回解析值、重新收集、截圖與基準比對；有差異就回報，不自行修正
  10. 收尾 — 刪除比對板並回報；由其他 skill 呼叫時回傳結構化結果

近似值比對板

Workflow F 與稽核規則 13 用來呈現近似值差異的工具，讓使用者直接看到差異再決定是否合併。

放在哪裡

  • 範圍所在頁面、既有內容右側 400px 的 Section
  • 名稱固定為 Token Review — temporary
  • 只新增這個 Section，不移動、不修改任何既有節點

每組內容

  • 視覺樣本：色塊、間距條、圓角方塊、文字樣本、陰影卡片、透明度方塊
  • 數值、使用次數、★ 建議值
  • 連到來源節點的 sample 超連結

決定與收尾

  • 截圖並提供 Figma 連結
  • 逐組選擇：合併到建議值、合併到其他值、全部保留
  • 套用後刪除 Section（使用者要求保留則保留）
類別 近似門檻
色彩CIE76 ΔE ≤ 3，且 paint 透明度相同
間距、尺寸、圓角、描邊寬度差 ≤ 1px，或 ≤ 較大值的 5%（取較大者）
文字同字型與字重，字級差 ≤ 1px、行高差 ≤ 2px、字距差 ≤ 0.2px
陰影陰影層數相同，各參數差 ≤ 1px，顏色 ΔE ≤ 3
透明度差 ≤ 5 個百分點

兩個值都在階梯上時（例如間距 2 與 4、hover 8% 與 focus 10%）不算近似值。建議值優先選擇在階梯上的值，否則選使用次數最多的值。

await textNode.setTextStyleIdAsync(textStyle.id)

// 陰影：綁定 effect 欄位後指定給 Effect Style
effect = figma.variables.setBoundVariableForEffect(effect, "radius", variable)

變體與互動狀態

Comp 名稱依 M3 目前的順序：元件 → variant → 選取狀態 → 互動狀態 → 結構 → 屬性。

State Token 命名

  • …/container/background-color — 預設
  • …/hovered/state-layer/opacity
  • …/pressed/state-layer/opacity
  • …/disabled/container/background-color
  • …/selected/container/background-color
  • …/error/outline/color

Variant 值對應

  • Hover、Hovered → hovered
  • Focus、Focused → focused
  • Press、Pressed → pressed
  • Drag、Dragged → dragged
  • Disabled、Selected、Unselected、Error → 同名小寫
  • Default、Enabled、Rest → 不加段落

State Layer 不透明度

  • Hovered — 8%
  • Focused — 10%
  • Pressed — 10%
  • Dragged — 16%

Disabled 狀態必須建立專用 token，不可重用預設 token：容器用 on-surface 搭配 disabled 容器透明度，內容用 on-surface 搭配 38%。透明度以 composed 色彩或圖層透明度表達，不要另外做一個不透明的新色。檔案若已使用 hover、focus 或把狀態放在屬性之後的舊順序，在使用者遷移前沿用原寫法（稽核規則 17 提供改名遷移，綁定不受影響）。

Light / Dark 雙模式擴展

System collection 新增 Dark mode，每個 Sys color 在 Dark mode 指向不同 tone 的 Ref。Comp 層與節點綁定都不需要修改。需要付費方案（Starter 每個 collection 只有 1 個 mode）。

// Light mode
sysPrimary.setValueForMode(lightModeId, figma.variables.createVariableAlias(refPrimary40))
// Dark mode
sysPrimary.setValueForMode(darkModeId, figma.variables.createVariableAlias(refPrimary80))

稽核規則 — 十八種規則

Workflow C 使用的完整規則。修正前一定先詢問，每個修正依變動分級確認；沒有發現問題時回報「checked rules 1–18」。

1

Comp 直接 alias Referror

Comp 的值（包含 composed 色彩的任一欄位）直接指向 Ref。修正：改指向對應的 Sys token。

2

Scope 錯誤error

ALL_SCOPES、非 Ref 的空 scope、Ref 有 scope、ALL_FILLS 與個別填色 scope 並用、scope 與型別不符。修正：依 scope 對照表設定。

3

WEB Code Syntax 缺少或不正確warning

修正：從名稱推導並覆寫。

4

Prefix 不一致error

同一檔案有兩種以上的 prefix。修正：確認 prefix 後改名（Tier 3）。

5

節點直接綁定 Referror

修正：改綁 alias 同一個 Ref 的 Comp 或 Sys token。

6

空的 Collectioninfo

修正：詢問後刪除（Tier 3）。

7

Ref 或 Sys 出現元件或區域名稱warning

修正：Ref 改為數值命名、Sys 改為共用語意，元件用法移到 Comp。

8

Alias 方向不合法error

只允許 Sys → Ref、Comp → Sys（composed 色彩的欄位也適用）。

9

缺少 Mode 值error

修正：補上缺少的值；Light/Dark 的 Sys 色彩指向正確的 Ref tone。

10

綁定型別與屬性不相容error

例如 FLOAT 綁到填色、COLOR 綁到圓角。修正：改綁正確型別的 variable（Tier 3）。

11

元件略過既有的 Comp tokenwarning

元件節點綁 Sys，但同元件已有 alias 同一個 Sys 的 Comp token。修正：改綁 Comp token。

12

Ref 名稱與數值不符error

例如 ref/spacing/16 的值是 12，或 ref/color/blue/50 的 L* 只有 28。修正：依數值改名，或修改數值（Tier 3）。

13

重複或近似重複的 Refwarning

例如 #1A73E8 與 #1A73E9。修正：在比對板上確認後合併（Tier 3）或保留。

14

間距標籤不一致warning

例如 inset-vertical-sm = 12、gap-inline-sm = 8。修正：改名讓每個標籤只代表一個值。

15

元件 token 覆蓋率warning

元件中寫死的填色、描邊、圓角、padding、gap、描邊寬度、文字與陰影；例如 14 個屬性綁了 10 個，覆蓋率 71%。修正：對該元件執行 Workflow F。

16

Styles 未綁定 variableswarning

Text Style 或 Effect Style 的欄位仍是原始值。修正：綁定數值相同的 Sys tokens。

17

舊式狀態順序warning

…/container/background-color/disabled → …/disabled/container/background-color。修正：原地改名，綁定與 alias 都不受影響。

18

名稱格式warning

大寫、空白或不允許的字元，例如 sys/color/Primary。修正：改名並更新 code syntax。
