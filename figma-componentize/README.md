# Figma Componentize 使用說明

把設計稿裡還沒做成元件的 UI 整理成元件，再把原本的圖層換成元件的 instance。**畫面看起來不會變。**

檔案裡已經有合適的元件時會直接沿用，沒有才建立新的。

## 什麼時候用

- 同樣的按鈕、卡片、列表項目畫了好幾份，想整理成元件
- 想把一個 section、一個 frame，或單一元素做成元件
- 只想把寫死的顏色、間距轉成 token，不做元件 → 請改用 `figma-m3-variables`
- 只想要一份設計系統文件（不做元件化）→ 也可以用這個 skill

## 開始前

- 你的 AI 工具（Cursor、Codex 或 Claude Code）要連上 **Figma 的遠端 MCP**，也就是能修改檔案的那種。Figma Desktop 的本機 MCP 只能讀取，不夠用。
- 第一次使用，先拿不重要的檔案試。

## 使用者旅程

```text
丟連結 → AI 掃描 → 你確認分組 → 你確認計畫 → 你存版本 → AI 建元件 → 你確認 token → 你確認替換 →（要的話）產生設計系統文件 → 看報告
```

標著「你決定」的步驟，AI 一定會停下來等你回覆。

### 1. 丟連結

在 Figma 選取要整理的範圍，右鍵 → **Copy link to selection**，貼給 AI：

```text
幫我把這個 section 元件化：https://www.figma.com/design/...
```

AI 會先截圖，記下畫面原本的樣子，最後拿來比對。

接著 AI 會多問兩個問題：

- 最後要不要順便產生一份「設計系統文件」？選「不要」就完全不產生，流程和原本一樣。
- 選「要」的話，文件的標題用哪一種語言？預設英文，也可以選繁體中文或其他語言。

### 2. AI 掃描（不會動任何東西）

AI 找出哪些 UI 還不是元件，把同一種的歸成一組。例如三顆按鈕歸成一個 `Button`，填色和外框成為它的兩個 variant。

同時會比對檔案裡的現有元件，看看哪些可以直接沿用。

### 3. 確認分組（你決定）

設計稿旁邊會出現一個暫時的區塊 **Componentize Review — temporary**，每一組並排顯示實際的樣子。配到現有元件的分組，現有元件也會排在旁邊讓你對照。

每一組你可以回答：**接受、改名、拆開、合併、排除**。

依情況，可能還會問你：

- 要沿用現有的 `Button` 嗎？
- 這顆外框按鈕在現有元件裡沒有對應的 variant，要「在現有元件加一個 variant」、「建立新元件」，還是「維持原樣」？
- 已經有同名的元件了，新元件要叫什麼？

確認完，這個區塊會被刪掉。

### 4. 確認計畫（你決定）

AI 列出要建立哪些元件、沿用哪些、排除哪些。你確認後，才會開始改檔案。

### 5. 存一個版本（你動手）

AI 沒辦法替你存版本，所以會請你按 **⌘⌥S**（Windows：Ctrl+Alt+S），名稱是「Before figma-componentize — 範圍名稱」。你回覆「存好了」，它才會繼續。

之後不滿意，隨時可以從版本紀錄回到這裡。

### 6. 建立元件，再轉成 token（你確認 token）

- 元件建在 **Components** 頁，由小到大：先建按鈕，再建裡面放著按鈕的卡片。
- 接著把元件上的顏色、字級、圓角、間距、陰影轉成 token。會再出現一個比對區塊 **Token Review — temporary**，很接近的數值（例如 `#1A73E8` 和 `#1A73E9`）要不要合併，由你決定。

到這一步，你的原稿都還沒被動到。

### 7. 換成 instance（你再確認一次）

AI 會問：**全部替換**、**選擇元件**，或**先不要**。就算你一開始說過「全部自動」，這裡還是會問。

替換時會逐一比對位置、尺寸、文字和樣式。一樣（或只差在你第 6 步同意合併的數值）才刪掉原本的圖層；有其他不同，就保留原稿，並告訴你差在哪。

### 8. 產生設計系統文件（你一開始選了「要」才有）

檔案裡會多一個 `Design System` 頁面（已經有設計系統或 Foundations 頁面時，就用那一頁）。文件全部放在一個叫 `Design System — generated` 的外框裡。

- **裡面有什麼**：檔案裡所有的 tokens（顏色、文字樣式、間距與尺寸、圓角、陰影等）和所有元件（每個 variant 的樣子、屬性、用到的 tokens）。小圖示集中在同一區。
- **樣本是活的**：色票、間距條這些樣本綁定 token，token 改了會跟著變。旁邊的文字（名稱、數值）是產生當下的紀錄。
- **只有標題會換語言**：文件自己的標題和欄位名稱用你選的語言。token 名稱、元件名稱、數值，和你寫的元件描述都照原樣，不翻譯。
- **不會改動你的檔案**：不建立也不修改任何 token、style 或元件，只是多了一份文件。
- **版型固定**：文件用固定的版型（Apple 風格）排版，每個專案的文件長得一樣，只有內容不同；封面有目錄，點一下就跳到該段落。[看版型範例](docs/document-template.html)

依情況，可能還會問你：

- 檔案很大（很多 tokens 或元件）：先告訴你數量，問你要全部產生、只產生一部分，還是略過。
- 已經有舊的文件：要「取代」、「保留舊的，在旁邊產生新的」，還是「略過」？取代前一定會再確認，因為你在舊文件外框裡改過的東西會不見。

### 9. 看報告

報告會告訴你：

- 建了哪些元件、沿用了哪些
- 換掉幾個、保留幾個，以及保留的原因
- 新建了哪些 token
- 你存的版本名稱，以及 Components 頁的連結
- 設計系統文件的連結（有產生的話）

## 範例：整理首頁

**情境**：Components 頁已經有 `Button`，但只有填色（`Style=Filled`）一種。首頁有兩顆填色按鈕、一顆外框按鈕，還有一張裡面也放著按鈕的卡片。

**你說**：

```text
幫我把首頁這個 section 元件化：https://www.figma.com/design/...
```

**結果**：

| 畫面上的 UI | 會發生什麼 |
|-------------|------------|
| 兩顆填色按鈕 | 直接沿用現有的 `Button`，不會問你 |
| 外框按鈕 | 問你要怎麼處理。選「在現有元件加一個 variant」的話，`Button` 會多一個 `Style=Outlined`，原本的 Filled 不會被動到 |
| 卡片 | 沒有現成的，所以建立新的 `Card`；裡面的按鈕是 `Button` 的 instance |

最後，首頁的這些圖層都換成 instance，畫面看起來和原本一樣。

如果一開始選了「要」，照上面的選法，文件裡會看到 `Button` 和它的兩個 variant（Filled、Outlined）、新的 `Card`，以及檔案裡所有的 tokens。

**只想要文件的話**，可以這樣說：

```text
幫我產生這個檔案的設計系統文件，用繁體中文
```

AI 會先請你存一個版本，告訴你檔案裡有多少 tokens 和元件，然後產生文件。不會做元件化。

## 常見問題

**有些圖層沒被換掉？**
報告會寫原因，例如外觀對不上、字型缺少、圖層被鎖定。被鎖定的圖層會先問你要不要解鎖。外觀只差一點點的，你看過差異後可以決定接受。

**做到一半想停？**
直接說停。在第 7 步選「先不要」，元件會留在 Components 頁，原稿不會被動到。一開始選了要產生設計系統文件的話，文件還是會產生；不想要就跟 AI 說略過。想全部還原，就回到第 5 步存的版本。

**會用到 team library 的元件嗎？**
不會，只看這個檔案裡的元件。

**散落的向量圖示會被做成元件嗎？**
不會，只會列在報告裡。

**檔案頁數滿了（免費方案最多 3 頁），沒辦法新增 Components 頁？**
AI 會請你選一頁，在那頁放一個 `Components` 區塊來放元件。設計系統文件也一樣：請你選一頁，放在那頁的一個 `Design System` 區塊裡。

**文件裡的用途說明從哪裡來？**
只來自你寫在 Figma 元件「描述」欄位的文字。沒寫就不顯示，AI 不會自己編。

**token 改了之後，文件會自動更新嗎？**
色票、間距條這些樣本會跟著變；旁邊的名稱和數值文字不會。說「幫我更新設計系統文件」，就會重新產生一份。

**可以改文件的內容嗎？**
可以，但 `Design System — generated` 外框裡的內容，重新產生並選「取代」時會被取代。自己的說明請放在外框外面，或寫在元件的描述欄位。
