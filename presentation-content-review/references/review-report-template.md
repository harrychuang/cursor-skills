# 審查報告結構

依這個結構輸出。替換中括號，刪掉不適用的段落，不留空白佔位符。判定只用「通過／需修改／缺少」，並附原文依據。

```markdown
# 簡報審查報告｜[簡報名稱或主題]

- 規則版本：[rules.md 的版本號]
- 審查範圍：[N 頁；哪些頁標為不適用，例如封面、附錄]
- 輸入來源：[檔名／貼上的文字／連結；若分頁是自行假設的，寫出切法]

## 總評

- 整體判定：[可送出／修改後可送出／需大幅修改；門檻見 rules.md「整體判定門檻」]
- 只讀標題的故事線：[把主體頁標題依序串成一段話，說明讀起來是否成立、缺哪一環]
- 最該先處理的事：[1–3 項，對應下方必改清單]

## 逐頁審查

### 第 [n] 頁｜[原標題]

| 檢查 | 判定 | 依據與說明 |
| --- | --- | --- |
| T1 標題＝結論（觀點＋行動） | [通過／需修改／缺少] | [引用原文，說明缺觀點還是缺行動] |
| S1 副標用理由補充 | [通過／需修改／缺少] | [引用原文] |
| E1 證據數 | [k／3，通過／需修改／缺少] | [算法：哪些算、哪些不算] |
| E2 證據四要素 | [通過／需修改] | [哪幾條缺哪個要素；細節見證據清單] |
| E3 支持結論 | [通過／需修改／缺少／無法判定] | [直接支持／部分相關／無關各幾條] |
| E4 強度標示 | [通過／需修改] | [原文有無把做法參考寫成成效] |
| 其他觸發的規則 | [規則 ID：判定] | [只列有問題的] |

證據清單：

1. [主體] 做了 [做法] → [成果]（來源：[來源]；強度：[已驗證成效／做法參考／預期待驗證]；缺：[缺哪幾個要素，沒有就寫「無」]；支持結論：[是／否，一句話]）
2. …

建議改寫：

- 標題：[一個結論：觀點＋行動]
- 副標：[理由]
- 證據：[保留哪些、刪哪些；缺的寫「【待補：需要什麼】」]

（每一頁重複上述區塊）

## 必改清單（依優先順序）

排序依 rules.md「必改清單排序」：整頁沒有有效證據 → 標題不是完整結論 → 結論矛盾 → 疑似捏造；同級依頁序。

1. 第 [n] 頁｜[規則 ID]｜[一句話說明問題與改法]
2. …

## 待補證據清單

| 頁 | 要支持的結論 | 需要的證據 | 目前狀態 |
| --- | --- | --- | --- |
| [n] | [標題結論] | [例如：某產品做了 X 之後的留存變化與來源] | [缺少／只有做法參考／已請使用者提供] |

## 本次未檢查的項目與限制

- [例如：無法讀取原檔中的圖表數字；未查證外部案例是否仍存在；視覺版面不在審查範圍]
```

## 精簡版（使用者只要重點時）

只輸出「總評」加「必改清單」加「待補證據清單」，逐頁表省略；但每個必改項仍要附規則 ID 與原文依據。

## 整份改寫版（使用者明確要求時）

每頁輸出：

```markdown
## 第 [n] 頁
- 標題：[觀點＋行動]
- 副標：[理由]
- 證據：
  1. [主體] 做了 [做法] → [成果]（來源；強度）
  2. …
  - 【待補：…】
```

文末附「待補證據清單」，不省略。
